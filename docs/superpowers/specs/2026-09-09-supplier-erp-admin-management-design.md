# 供应商 ERP 接入与后台统一管理设计

日期：2026-09-09

## 目标

本次改造同时解决两个问题：

1. 管理后台以业务对象重新分组，统一供应商与运营商管理页面的视觉和交互风格。
2. 将 ERP API 接入权限归还真正的数据主体——供应商。运营商只参与合作，不拥有 ERP API 凭证。

本期 ERP API 仅提供只读能力，不允许外部系统新增或修改平台数据。

## 已确认范围

- 管理后台改为“供应商管理、运营商管理、合作管理、平台管理”四个分组。
- 合作记录独立于供应商和运营商管理。
- 供应商工作台新增“ERP 接入”。
- 管理后台原“集成凭证”改名为“平台 API 凭证”。
- 删除运营商工作台的凭证管理页面和相关业务接口。
- 数据升级时直接删除全部现有运营商 API 凭证，不保留历史凭证记录。
- 供应商 API 凭证只能读取本供应商组织的数据。
- 平台 API 凭证继续支持平台范围的只读集成。
- 原“ERP 绑定 UUID”在界面上改称“合作绑定 UUID”，只表示合作关系，不赋予 API 权限。

## 信息架构

### 管理后台

左侧导航调整为：

- 供应商管理
  - 入驻申请
  - 供应商列表
- 运营商管理
  - 入驻申请
  - 运营商列表
- 合作管理
  - 合作记录
- 平台管理
  - 平台 API 凭证
  - 平台能力

默认仍进入供应商入驻申请，现有 URL hash 保持兼容，避免收藏链接失效。

供应商和运营商的入驻申请页面统一使用：标题与说明、申请入口和刷新操作、统计卡片、关键词搜索、状态筛选、数据表格、空状态、审核操作以及统一分页。

供应商列表和运营商列表统一使用：标题与说明、关键词搜索、记录数量、状态展示、表格容器、空状态和统一分页。双方特有字段继续分别展示，不为视觉一致而丢失业务信息。

合作记录使用独立分组，展示运营商、供应商、合作状态、合作绑定 UUID、申请与响应时间。它不归属任何一方的管理菜单。

### 供应商工作台

新增“ERP 接入”导航和页面，包含：

- 只读 API 基础地址和认证方式。
- 可申请的权限范围及中文说明。
- 创建凭证表单。
- 凭证列表、状态、到期时间、最近使用时间。
- 轮换和撤销操作。
- 明文令牌一次性展示与复制提醒。

供应商可以管理本组织创建的凭证，不能查看其他组织的凭证。明文令牌只在创建或轮换响应中返回，列表永远不返回明文。

### 运营商工作台

删除“接入凭证”导航、页面、脚本逻辑和创建/轮换/撤销接口。运营商仍能：

- 浏览供应商。
- 发起并管理合作申请。
- 查看合作绑定 UUID。
- 维护运营商资料。

运营商不再能用 Bearer Token 调用集成 API。

## 凭证模型

`IntegrationClient` 保留两种有效类型：

- `SYSTEM`：平台级凭证，`owner_organization_id` 必须为空。
- `SUPPLIER`：供应商级凭证，`owner_organization_id` 必须指向供应商组织。

移除 `OPERATOR` 作为可用凭证类型。数据库约束同步修改，阻止创建无所有者的供应商凭证或带所有者的平台凭证。

供应商创建凭证时，服务端从当前会话确定 `owner_organization_id`，不接受前端传入组织 ID。供应商只能选择只读 scope；重复 scope 由服务端去重。

## API 与权限边界

### 凭证管理接口

新增供应商会话接口：

- `GET /api/supplier/integration-clients`
- `POST /api/supplier/integration-clients`
- `POST /api/supplier/integration-clients/{client_id}/rotate`
- `POST /api/supplier/integration-clients/{client_id}/revoke`

所有接口要求有效供应商账号和有效供应商组织。资源查询必须同时匹配凭证 ID、`SUPPLIER` 类型和当前组织 ID；不匹配统一返回 404，避免暴露其他组织资源是否存在。

管理员现有凭证接口调整为：

- 创建和轮换仅用于 `SYSTEM` 平台凭证。
- 列表可以查看平台凭证和供应商凭证的元信息。
- 管理员可以撤销供应商凭证，但不能获得其明文令牌，也不能替供应商轮换后查看新令牌。

### 集成读取接口

Bearer Token 认证成功后，根据凭证类型确定数据范围：

- `SYSTEM`：保持现有平台范围读取能力。
- `SUPPLIER`：所有供应商、品牌、SKU、成本与详情查询强制限定到 `owner_organization_id`。

供应商凭证访问其他供应商 ID 时返回与资源不存在相同的 404 响应。列表接口只返回本供应商的数据；批量查询中不属于本供应商的条目按现有“资源不存在”错误结构返回。scope 校验继续生效，凭证类型不能绕过 scope。

所有集成端点维持只读；不新增 POST、PATCH 或 DELETE 业务数据接口。

### 合作绑定

`ErpBinding` 数据结构本期不重命名，避免无业务价值的大范围表迁移；页面与文档统一使用“合作绑定 UUID”。该 UUID 不参与 Bearer Token 鉴权，也不扩大供应商或运营商的数据权限。

## 数据迁移

Alembic 升级按以下顺序执行：

1. 删除 `integration_clients` 中所有 `client_type = 'OPERATOR'` 的记录。
2. 删除旧的凭证所有者检查约束。
3. 创建仅允许 `SYSTEM` 与 `SUPPLIER` 的新约束。

删除是用户明确选择的不可恢复操作。迁移 downgrade 只能恢复旧约束结构，无法恢复已删除的运营商令牌；设计和迁移说明必须明确这一点。

与已删除凭证相关、但存储在通用事件表中的历史审计事件不主动清理，因为它们不包含可使用的明文令牌，也有助于解释历史操作。

## 前端状态与错误处理

- 供应商凭证创建和轮换期间禁用提交按钮，防止重复签发。
- 创建或轮换成功后使用警示对话框展示一次性令牌；关闭、取消和退出页面时清空 DOM 中的令牌文本。
- 复制失败时提供手动复制提示。
- 撤销前要求确认，成功后刷新列表。
- 跨组织资源统一显示“凭证不存在或不可访问”，不显示真实所有者。
- 后台两类申请页面使用一致的加载、无结果和请求失败状态。
- 页面保留统一分页控件，并支持 20、50、100、200 条每页。

## 安全要求

- 不在日志、数据库列表响应或审计 payload 中记录明文令牌。
- 创建和轮换响应设置 `Cache-Control: no-store`。
- 供应商组织或用户停用后，其会话管理接口不可用；其 Bearer Token 也必须认证失败。
- 删除运营商凭证后，旧令牌立即失效。
- 服务端权限判断不依赖前端隐藏按钮。
- 平台管理员不能通过普通列表重新获得任何凭证明文。

## 测试与验收

### 数据与迁移

- 升级会删除运营商凭证，保留平台凭证。
- 新约束允许合法的 `SYSTEM`、`SUPPLIER` 记录并拒绝非法所有者组合。
- downgrade 行为明确且不声称能恢复已删除凭证。

### API

- 供应商可以创建、列出、轮换和撤销本组织凭证。
- 供应商无法操作其他供应商凭证。
- 供应商凭证只能读取本组织数据。
- 跨供应商详情、SKU 与成本查询返回 404 或批量资源不存在错误。
- 供应商凭证无法写入业务数据。
- 运营商凭证管理接口不存在或返回 404，历史运营商令牌认证失败。
- 平台凭证保持现有读取能力。
- 停用用户、组织或凭证均不能继续访问。

### 前端

- 管理后台分组、标题、面包屑和页面名称符合新信息架构。
- 供应商与运营商申请及列表页面的结构和视觉类名保持一致。
- 合作记录位于独立分组。
- 供应商 ERP 接入页正确处理一次性令牌、分页和错误状态。
- 运营商工作台不存在凭证入口。
- 所有新增 JavaScript 通过语法检查和行为测试。

### 发布

- 完整后端和前端测试通过。
- 独立代码复审无 Critical 或 Important。
- 合并到 `main` 后再次运行完整测试。
- 使用项目启动脚本重启服务。
- 检查数据库迁移 head、容器健康状态、管理后台、供应商 ERP 接入页和运营商工作台。

## 不在本期范围

- ERP 向平台写入商品、报价或库存。
- 运营商 API 凭证或运营商 ERP 数据同步。
- 供应商向运营商发起合作。
- 重命名 `erp_bindings` 数据库表。
- 多级审批、IP 白名单、Webhook 或细粒度字段权限。
