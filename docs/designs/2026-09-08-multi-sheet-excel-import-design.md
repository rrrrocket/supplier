# Excel 多工作表导入设计

状态：已确认
日期：2026-09-08

## 1. 目标

- 供应商上传 `.xlsx` 或 `.xls` 后，可以选择一个或多个工作表导入。
- 每个选中工作表独立设置表头行、字段映射和默认值。
- 所有选中工作表先汇总预览，再作为一个批量导入任务提交。
- 跨工作表出现相同供应商 SKU 时不得静默覆盖，必须人工解决冲突。
- 兼容腾讯文档生成、Excel 能打开但 `openpyxl` 无法直接读取的空 Fill 样式。
- CSV、TSV、TXT 和 PDF 保持现有单数据源导入流程。

## 2. 用户流程

### 2.1 扫描工作簿

用户选择 Excel 文件后，页面立即调用只读扫描接口。接口返回：

- 工作表名称及顺序。
- Excel 中的活动工作表。
- 预计数据行数和列数。
- 建议表头行。
- 表头及前几行样例。
- 系统能够高置信识别的建议字段映射。

扫描和预览阶段均不写入业务数据库。浏览器在扫描、预览和最终导入时复用并重新上传当前选择的 `File` 对象，服务端不保存临时 Excel 文件。

页面默认勾选 Excel 的活动工作表。用户可以取消、单选、多选或全选。当前 `Trumpeter.xlsx` 的活动工作表是 `Sheet1`，因此默认选择 `Sheet1`，不再由数据行数决定目标工作表。

### 2.2 每个工作表独立配置

每个选中工作表显示一张独立配置卡：

- 表头行号。
- 商品名称、供应商 SKU、成本价和类目映射。
- 品牌、型号、币种、MOQ、库存、交期、履约模式和状态等可选映射。
- 该工作表自己的默认值。
- 该工作表的原始样例行。

列的稳定标识使用 Excel 列字母，不使用可能重复或为空的表头文本。显示名称规则为：

- 有表头：`C列 · 编号`。
- 无表头：`C列（无表头）`。
- 重复表头：仍通过不同列字母区分。

系统只自动采用高置信映射。低置信或无表头字段必须在卡片中确认，不允许靠列位置静默猜测。对于当前 `Sheet1`，目标映射为：

| Excel 列 | 目标字段 |
|---|---|
| C | 供应商 SKU |
| E | 商品名称 |
| N | 品牌 |
| O | 型号/比例 |
| P | 类目 |
| R | 成本价 |

成本列使用 `data_only=True` 读取 Excel 已保存的公式结果。若公式没有缓存结果，该单元格按缺失成本处理并在预览中报错，不在服务端计算任意 Excel 公式。

### 2.3 汇总预览和冲突解决

点击“生成合并预览”后，服务端按每个工作表自己的配置标准化数据。每行额外保留：

- `source_sheet`：来源工作表。
- `source_row`：Excel 原始行号。
- `included`：最终是否保留。

页面可以按来源工作表或冲突状态筛选，也可以查看全部数据。标准化后的完整数据保存在页面状态中，每页只渲染 50 行；翻页、筛选和编辑都更新同一份完整数据，最终提交不得从当前页 DOM 临时拼接，避免遗漏未显示的行。所有选中工作表的有效数据总量合计不得超过 10,000 行。

如果同一次预览中存在相同的非空供应商 SKU：

- 将全部重复记录归为一个冲突组并标红。
- 默认不自动选择胜出记录。
- 用户必须选择保留其中一条，或者编辑 SKU 使其不再重复。
- 任一冲突未解决时禁用“确认导入”。

该规则只处理本次提交中的重复记录。与数据库中已有供应商 SKU 相同的记录继续沿用现有 Upsert 行为。

### 2.4 确认导入

最终导入继续创建一个 `ImportJob`，汇总记录总数、成功数和失败数。错误信息增加 `sheet` 和 `row`，页面显示来源工作表及原始行号。

服务端不得只信任前端的“冲突已解决”状态。提交时重新验证：

- 至少保留一行。
- 所有必填字段存在。
- 所有保留行的供应商 SKU 在本次提交中唯一。
- 行数不超过 10,000。
- 来源工作表属于本次配置中的选中工作表。

## 3. 接口设计

### 3.1 工作簿扫描

新增：

```text
POST /api/imports/product-offers/workbook/inspect
Content-Type: multipart/form-data
file=<xlsx-or-xls>
```

返回结构：

```json
{
  "file_name": "Trumpeter.xlsx",
  "active_sheet": "Sheet1",
  "sheets": [
    {
      "name": "Sheet1",
      "index": 0,
      "estimated_rows": 3694,
      "column_count": 27,
      "suggested_header_row": 1,
      "columns": [
        {"key": "C", "header": "", "label": "C列（无表头）"},
        {"key": "R", "header": "成本", "label": "R列 · 成本"}
      ],
      "sample_rows": []
    }
  ]
}
```

该接口只接受 `.xlsx` 和 `.xls`，沿用 10 MiB 上传限制。

### 3.2 多工作表预览

现有预览接口保留：

```text
POST /api/imports/product-offers/preview
```

Excel 请求新增 `sheet_configs_json` 表单字段，其内容为数组：

```json
[
  {
    "sheet_name": "Sheet1",
    "header_row": 1,
    "mapping": {
      "supplier_sku": "C",
      "product_name": "E",
      "brand": "N",
      "model": "O",
      "category": "P",
      "price": "R"
    },
    "defaults": {"currency": "CNY"}
  }
]
```

响应的预览行增加 `source_sheet`、`source_row`、`included` 和可空的 `conflict_group`。响应同时返回冲突总数；存在未解决冲突时 `can_import` 为 `false`。

未提供 `sheet_configs_json` 时继续支持现有单表自动预览，避免破坏已有调用方。页面的新 Excel 流程必须提供显式配置。

### 3.3 最终导入

现有最终导入接口继续接收 `rows_json`。标准行允许附带 `source_sheet`、`source_row` 和 `included`。服务端过滤 `included=false` 的记录后重新执行必填字段、数值和重复 SKU 校验。

## 4. 解析器结构

将当前“读取文件并立即选出一个最佳表”的逻辑拆成三个职责：

1. `inspect_workbook`：列出工作表、活动页、样例、建议表头和列描述。
2. `parse_selected_sheets`：严格按 `sheet_configs_json` 解析选中的工作表。
3. `normalize_rows`：沿用已有标准字段和默认值处理，并附加来源信息。

工作表名称必须与工作簿中的名称完全匹配；配置中不允许重复工作表。表头行必须为正整数且实际存在。字段映射只接受扫描结果中的列字母。

## 5. 腾讯文档 XLSX 兼容

当前 `Trumpeter.xlsx` 的 `xl/styles.xml` 含空 `<fill/>` 节点。Excel 可以打开，但 `openpyxl` 3.1 会在读取工作簿内容前抛出 `TypeError: expected Fill`。

解析流程先尝试正常读取。仅在样式解析失败且确认存在空 Fill 节点时：

1. 在内存中复制 XLSX ZIP 包。
2. 将空 Fill 补成合法的无填充 `patternFill`，保持 Fill 数量和索引不变。
3. 用修正后的内存字节重新读取。

不得修改用户原文件，不得把修正版写入仓库或业务存储，不得忽略其他 ZIP、加密或工作簿结构错误。

## 6. 页面状态与错误处理

导入页面增加四个明确状态：

1. `未选择文件`
2. `正在扫描工作簿`
3. `配置工作表`
4. `预览并解决冲突`

更换文件时必须清空此前的工作表选择、映射、预览和冲突状态。扫描或预览失败时保留文件选择，允许调整后重试。

错误提示必须区分：

- 文件损坏或加密。
- 没有可读取的工作表。
- 未选择工作表。
- 表头行不存在。
- 必填字段未映射。
- 选中数据超过 10,000 行。
- 重复 SKU 尚未解决。

## 7. 测试与验收

测试采用先失败、后实现的顺序，覆盖：

- 腾讯文档空 Fill 样式可在内存中兼容读取，原始字节不变。
- 扫描结果返回全部工作表及正确活动页。
- 当前 `Trumpeter.xlsx` 默认活动页为 `Sheet1`；人工验收时使用 C/E/N/O/P/R 映射得到约 3,694 条预览数据。
- 单选和多选工作表均可独立指定表头、映射及默认值。
- 无表头和重复表头使用列字母稳定区分。
- 汇总行保留来源 Sheet 和原始行号。
- 3,694 行以上的预览采用每页 50 行分页，翻页和筛选不会丢失编辑结果或未显示行。
- 跨 Sheet 重复 SKU 产生冲突且 `can_import=false`。
- 选择保留记录或编辑 SKU 后可以导入。
- 服务端拒绝绕过前端提交重复 SKU。
- 数据总量按所有选中工作表合计限制为 10,000 行。
- CSV、TSV、TXT、PDF 和原有单 Sheet Excel 测试继续通过。
- 前端脚本语法检查及交互状态测试通过。
- `./start.sh test` 全量通过，服务健康检查正常。

## 8. 不在本次范围

- 不在服务端执行 Excel 公式或宏。
- 不保存上传的原始工作簿或兼容后的副本。
- 不增加后台异步导入队列。
- 不改变数据库中已有 SKU 的 Upsert 规则。
- 不实现跨多个 Excel 文件的一次性合并导入。
